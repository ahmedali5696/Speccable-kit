# Contributing to Speccable-kit

Thanks for your interest. Speccable-kit is an **extension-only** Spec Kit integration — it
ships no Preset, forks no Spec Kit core, vendors none of Impeccable, and stays
**agent-neutral**. Please keep those boundaries intact.

## Ground rules

- The **source of truth is `extension/`**. Never edit the materialized copies under
  `.specify/extensions/speccable/` or `.zcode/skills/speckit-speccable-*`; they are
  git-ignored byproducts of `specify extension add`.
- **Respect the boundaries.** No modification/fork of Spec Kit core or its templates. No
  vendoring/forking of Impeccable, and no writes inside Impeccable's namespace
  (`.impeccable/`, `PRODUCT.md`, `DESIGN.md`, surface briefs). No auto-install or
  auto-upgrade of Impeccable. No provider-specific installation logic, commands, hooks, or
  environment variables — agent integration is Spec Kit's job, not Speccable's.
- **Behavioral contracts are load-bearing.** When you change a command or script, keep:
  - a valid human-authored `UI Impact` value preserved verbatim;
  - classification failure `BLOCK`s (never silently default to `none`);
  - `NOT_RUN` never equals `PASS`;
  - only primary findings materialized into `tasks.md`, deduplicated under
    `## UI Validation Follow-ups`, without modifying `/speckit-converge`.
- Hook declarations stay condition-free; routing lives inside the command implementation.

## Local development

Prerequisites: Python 3.11+, Node.js, Windows PowerShell (5.1) or PowerShell Core (`pwsh`)
for the `.ps1` scripts, and the `specify` CLI (>= 1.0.1) if you run the native-install or
clean-room tests.

```bash
# Run the contract suite
python -m unittest tests.test_contract -v

# Re-sync your local installed copy after editing extension/
specify extension add ./extension --dev --force

# Clean-room install + layout-matrix evidence harness (writes docs/validation/cleanroom-evidence.json)
python tests/run_cleanroom.py
```

See [docs/speccable/development.md](./docs/speccable/development.md) for the full guide,
including the exact PowerShell/Node runtime matrix.

## Tests

All changes should keep the full suite green (`python -m unittest tests.test_contract`).
Add a regression test for any behavior you change, especially in the executable validator
(`tests/test_contract.py::TestValidateDetectorExecutable`).

## Committing and releasing

- Version is `SemVer`; the authoritative copy is `extension.version` in
  `extension/extension.yml`. Update the manifest, `CHANGELOG.md`, and `README.md` together
  in the same change. Tag releases `v<version>` (e.g. `v1.0.0`).
- Do not commit generated byproducts (`.specify/extensions.yml`, `.specify/extensions/`,
  `.zcode/skills/speckit-speccable-*`, `__pycache__/`).

## Reporting issues

Open a GitHub issue with a clear title, the version in use, your runtime (OS, PowerShell /
Node), and when relevant the `UI Impact`, routing state, and any validator output.
